== Plugin bauen

```bash
cd ../jenkins-gretl-datenportal-plugin
export JAVA_HOME="$HOME/.sdkman/candidates/java/21.0.10-tem"
export PATH="$JAVA_HOME/bin:$PATH"
mvn -ntp package
```

Die Tests und das HPI laufen auf Java 21.

== In die lokale Jenkins-Umgebung integrieren

```bash
cd ../datenportal-jenkins-dev
./bin/install-gretl-datenportal-plugin.sh
./bin/start.sh
```

Danach in Jenkins:

. den automatisch angelegten Job `gretl-datenportal-seed` manuell starten oder
  auf den Cron-Lauf warten;
. `/gretl-datenportal` oeffnen;
. eine Organisation und einen Datensatz waehlen;
. mindestens `METADATA_FILE` oder `DATA_FILE` hochladen;
. den generierten Job starten.

== Was lokal verifiziert werden sollte

Typische manuelle Pruefpunkte:

* Scan-Meldungen und Seed-Fehlerverhalten;
* Sichtbarkeit von Organisationen ueber `permissions.read`;
* Startberechtigung ueber `permissions.build`;
* Jenkinsfile-Aufloesung und Placeholder im repo-weiten Default;
* Weitergabe von Upload-Dateien und Parametern an den generierten Job.
